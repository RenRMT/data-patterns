Data patterns

Data patterns are named and reusable solutions to recurring problems in how data is structured, moved, trusted, and looked after. They outline proven ways to organise data and information. The patterns described in this library outline. In contrast to the code patterns this catalogue is modeled after, data generally outlives the code around it. While a poor code pattern can often be refactored in short time, a poor data pattern can spread into every table, report and integration. Picking the right data pattern early can prevent this.

This page covers four groups of data patterns: - Patterns relating to the **structure** of data; - Patterns relating to the **movement** of data; - Patterns relating to the **trust** in data; - Patterns relating to **looking after** your data. These patterns are not recipes, and you should not just copy and paste all of them into your datasets. Apply the patterns in proportion to what is at stake: How much is enough says which ones you need for a one-off analysis and which ones for a donor report.
